1. What NearSend does

NearSend is a browser-based tool for connecting devices and transferring files. Transfers are intended to occur directly between browsers when WebRTC connectivity succeeds. If direct connectivity fails, the current implementation may use a WebSocket relay. As a result, do not assume every transfer is always end-to-end direct.

2. Your responsibility

  • Only connect to devices you recognize and trust.
  • Only send files you have the right to share.
  • Check incoming files with appropriate security software before opening them.
  • Do not use NearSend to distribute unlawful, harmful, or infringing content, or to interfere with the service.

3. Availability and reliability

NearSend is provided on an “as is” and “as available” basis. Connections can fail because of browser support, network restrictions, device sleep, firewalls, hosting limits, or service interruptions. Keep both devices and browser tabs open until a transfer finishes, and verify the received file before deleting your original.

4. Files and storage

NearSend does not provide a persistent file library or promise to retain transferred files. The receiver’s browser may temporarily hold file chunks in memory to assemble the download. When relay fallback is used, file data may pass through the signaling service while being forwarded. Do not use the service for files that require a guaranteed confidential or regulated transfer channel.

5. Security

Connection requests should be accepted only when you recognize the requesting device. Device names are user-editable labels, not proof of identity. You are responsible for deciding whether to accept a connection or a file.
